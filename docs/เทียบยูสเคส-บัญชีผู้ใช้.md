สถานะระบบ: หน้าบ้านล้วน ยังไม่มี backend — ข้อที่ต้องใช้เซิร์ฟเวอร์จึงยังทำไม่ได้จริง

สัญลักษณ์ ✅ ตรง · ⚠️ ตรงบางส่วน · ❌ ยังไม่มี · ⛔ ทำต่างจากเอกสารเพราะเจ้าของสั่ง

| 5 | แก้ชื่อผู้ใช้ / สุ่มรหัสใหม่ได้ | ✅ |

| S-1 | รีเซ็ตรหัสผ่าน | ✅ |
| S-2 | ระงับบัญชีเมื่อลาออก (ไม่ลบ) | ✅ ระงับได้ · ⛔ แต่ระบบ **ลบบัญชีได้ด้วย** ตามที่เจ้าของสั่ง 30 ก.ย. ซึ่งขัดกับ BR-01 |
| S-3 | คืนสิทธิ์ | ✅ |
| S-4 | ชื่อซ้ำเติมเลข | ✅ |
| S-5 | กำหนด/แก้บทบาท + ลงประวัติ | ✅ และตอบคำถามที่ค้างในเอกสารแล้ว: **บทบาทมาจากตำแหน่งอัตโนมัติ และ HR แก้เองได้** ตำแหน่งไหนได้บทบาทใดตั้งได้ที่หน้าตำแหน่งและสายอนุมัติ |
| BR-02 | สร้างได้เฉพาะพนักงานที่มีข้อมูลแล้ว · หนึ่งคนหนึ่งบัญชี | ✅ |
| BR-04 | ไม่มีช่องอีเมลในบัญชี | ✅ |

**คำถามที่เอกสารค้างไว้ — ระบบตอบไปแล้ว**
- บทบาทมาจากตำแหน่ง: ใช่ ตั้งได้เอง (ตำแหน่ง → ตำแหน่งในระบบ)
- บัญชี CEO: ไม่อยู่ในทะเบียนพนักงาน จึงไม่มีในหน้านี้ ยังต้องยืนยันว่าใครสร้าง
- สร้างบัญชีตอนเพิ่มพนักงาน หรือแยกหน้า: ระบบทำ **แยกหน้า** และหน้าเพิ่มพนักงานบอกไว้ว่าคนนี้จะได้บทบาทอะไร

## สรุปสิ่งที่ต้องตัดสินใจ

1. **ลบบัญชีได้หรือไม่** — เอกสารห้ามลบ (BR-01) ระบบทำได้ตามที่สั่ง ต้องเลือกว่าจะเก็บปุ่มลบไว้หรือเหลือแค่ระงับ
2. **รูปแบบชื่อผู้ใช้** — เอกสารว่า "ชื่อไทย.อักษรแรกนามสกุล" ระบบใช้ชื่ออังกฤษชื่อต้น ต้องแก้เอกสารหรือแก้ระบบ
3. **หน้าเข้าสู่ระบบ** — การ์ดเลือกบทบาทเป็นของเดโม ตอนต่อ backend ต้องเอาออก
4. **สถานะบัญชีต้องเก็บตามคน** ไม่ใช่ตามบทบาท เมื่อหนึ่งบทบาทมีหลายคน
5. ข้อที่ต้องรอ backend: เข้ารหัสรหัสผ่าน · ประวัติเข้า-ออกทุกครั้ง · เซสชันหมดอายุ · ปลดระงับอัตโนมัติ
