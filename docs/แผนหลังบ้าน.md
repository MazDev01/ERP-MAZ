# แผนสร้างหลังบ้าน ERP MAZ

แบ่งเป็นรอบตามลำดับที่ข้อมูลพึ่งพากัน รอบหลังใช้ของจากรอบหน้า จึงข้ามลำดับไม่ได้
วิธีทำงานทุกรอบเหมือนกัน — เขียน migration → รันบนเครื่อง → ทดสอบด้วยผู้ใช้จริงหลายบทบาท → commit

## หลักที่ยึดทุกรอบ

- **สิทธิ์ตัดสินที่ฐานข้อมูล** ด้วย RLS ไม่ใช่ที่โค้ดหน้าเว็บ ต่อให้ยิง API ตรงก็เห็นได้แค่ของตัวเอง
- **ของที่ย้อนไม่ได้ต้องผ่านฟังก์ชัน** ไม่ให้เขียนตารางตรง ๆ เช่นการตอกบัตรและการตัดสินใบ
- **เวลาและเลขที่เอกสารมาจากฐานข้อมูล** เครื่องผู้ใช้กำหนดเองไม่ได้
- **ย้อนอะไรต้องมีเหตุผทุกครั้ง** และเก็บไว้ให้สืบได้ว่าใครทำเมื่อไร
- **หน้าจอยังเดินด้วยข้อมูลในเครื่องได้** จนกว่าจะต่อส่วนนั้นจริง เพื่อให้เปลี่ยนทีละส่วนและย้อนได้

## สิ่งที่ไม่ได้ทำเป็นฟังก์ชันในฐานข้อมูล

**การสร้างบัญชีและตั้งรหัสผ่าน** ต้องทำผ่านฝั่งเซิร์ฟเวอร์ของ Next ไม่ใช่ SQL
เพราะการสร้างผู้ใช้อยู่ในระบบ auth ของ Supabase ซึ่งเขียนตรงจาก SQL ไม่ได้อย่างปลอดภัย
จึงต้องเป็น Route Handler ที่ถือกุญแจ service role แล้วเรียก Admin API

สามเส้นทางที่ต้องมี
- `POST /api/accounts` ฝ่ายบุคคลสร้างบัญชีให้พนักงานใหม่
- `POST /api/accounts/reset` ฝ่ายบุคคลรีเซ็ตรหัสผ่าน
- `POST /api/accounts/password` เจ้าตัวตั้งรหัสใหม่ครั้งแรก

**สูตรคำนวณเงินเดือน** ยังอยู่ใน TypeScript ฐานข้อมูลรับแค่ยอดที่คำนวณมาแล้ว
ถ้าอยากกันการแก้ยอดจริง ๆ ต้องย้ายสูตรลงมา ซึ่งเป็นงานใหญ่และควรทำหลังต่อหน้าจอเสร็จ

## หลังสร้างครบแล้วต้องทำอะไรต่อ

1. เติมข้อมูลตั้งต้น (`supabase/seed.sql`) ตอนนี้ฐานข้อมูลว่าง ทดสอบทีต้องสร้างพนักงานเอง
2. สร้างโครงการบนคลาวด์ แล้ว `supabase db push` ส่ง migration ขึ้นไป · เปิด hook ที่ Dashboard
3. ต่อหน้าจอทีละหน้า ล็อกอิน → ตอกบัตร → คำขออนุมัติ → เงินเดือน → ตั้งค่า
   พร้อมย้ายข้อมูลเดิมใน localStorage ขึ้นหรือทิ้ง ไม่งั้นผู้ใช้เห็นข้อมูลคนละชุด
