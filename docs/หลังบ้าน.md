# หลังบ้านของ ERP MAZ

ฐานข้อมูลเป็น PostgreSQL ผ่าน Supabase · สิทธิ์ตัดสินที่ฐานข้อมูลด้วย RLS ไม่ใช่ที่โค้ดหน้าเว็บ

ระบบยังเปิดใช้ได้ตามปกติแม้ยังไม่ตั้งค่าฐานข้อมูล — หน้าจอจะเดินด้วยข้อมูลในเครื่อง
(localStorage) เหมือนเดิม ส่วนที่ต่อแล้วจะเปลี่ยนไปอ่านจากฐานข้อมูลเองเมื่อมีค่าครบ

## ทำไมถึงเลือกแบบนี้

- **เวลาตอกบัตรต้องโกงไม่ได้** เวลาและการตรวจรัศมีคิดที่ฐานข้อมูล ไม่ใช่ที่เครื่องผู้ใช้
- **สิทธิ์ต้องกันที่ชั้นข้อมูล** ต่อให้ใครเรียก API ตรง ๆ ก็เห็นได้แค่ของตัวเอง
- **ไม่มีเซิร์ฟเวอร์ให้ดูแลเพิ่ม** Supabase ให้ auth, storage และ RLS มาในชุดเดียว

## รันบนเครื่องตัวเอง

ต้องมี Docker เปิดอยู่

```bash
npx supabase start          # ครั้งแรกจะดาวน์โหลดอิมเมจ ใช้เวลาหลายนาที
```

คัดค่า `API_URL`, `ANON_KEY`, `SERVICE_ROLE_KEY` ที่พิมพ์ออกมาใส่ `.env.local`
ดูรูปแบบได้ที่ [.env.example](../.env.example)

| อะไร | ที่อยู่ |
|---|---|
| API | http://127.0.0.1:58321 |
| ฐานข้อมูล | postgresql://postgres:postgres@127.0.0.1:58322/postgres |
| หน้าจอดูข้อมูล (Studio) | http://127.0.0.1:58323 |
| กล่องอีเมลทดสอบ | http://127.0.0.1:58324 |

พอร์ตขยับจากค่าตั้งต้น 543xx เป็น 583xx เพราะเครื่องที่ใช้พัฒนามีสแต็ก Supabase
ของโปรเจคอื่นรันอยู่ด้วย ถ้าเครื่องไหนว่างจะย้ายกลับก็ได้ แก้ที่ `supabase/config.toml`

```bash
npx supabase db reset       # ล้างแล้วลง migration ใหม่ทั้งหมด
npx supabase stop           # ปิด
```

  และคำนวณระยะห่างจากจุดเข้างานด้วยสูตร haversine ตัวเดียวกับ `work-area.ts`

- ทุกตารางเปิด RLS · ยังไม่ล็อกอินไม่เห็นอะไรเลย · พนักงานเห็นแค่ของตัวเอง · บทบาท `hr` เห็นทุกคน
- รหัสผ่านผิดครบ 5 ครั้งระงับบัญชีอัตโนมัติ (ตรงกับ `MAX_TRIES` ในหน้าล็อกอิน)
- รูปโปรไฟล์อยู่ใน bucket `avatars` แบบไม่เปิดสาธารณะ แยกโฟลเดอร์ตามรหัสพนักงาน

**ยังไม่มีในรอบนี้** — ลา · โอที · เบิกค่าใช้จ่าย · เงินเดือน · งานขาย · บัญชี · PM

## ต้องเปิดเองหลังสร้างโครงการบนคลาวด์

`custom_access_token_hook` ใส่บทบาทและสถานะบัญชีลงใน token ให้ `proxy.ts` ใช้นำทาง
บนเครื่องตัวเองเปิดไว้ใน `supabase/config.toml` แล้ว แต่โครงการบนคลาวด์ต้องไปเปิดเองที่
**Dashboard → Authentication → Hooks → Customize Access Token**
ถ้าลืมเปิด ระบบยังใช้ได้แต่จะไม่รู้ว่าใครต้องตั้งรหัสใหม่ก่อนเข้าใช้งาน

## ค่าใน token ใช้ได้แค่ไหน

`claims.app` มี `emp`, `roles`, `must_change`, `status` — **ใช้นำทางเท่านั้น**
สิทธิ์จริงตัดสินที่ RLS ซึ่งอ่านตารางสดทุกครั้ง เพราะ token ที่ออกไปแล้ว
ยังมีอายุเหลืออยู่แม้ HR จะเพิ่งระงับบัญชีไป

## ของเก่าที่ต้องล้าง

`prisma/schema.prisma` กับสคริปต์ Prisma เป็นของโปรเจค "MAZ HRM" คนละตัว ติดมาตั้งแต่
commit แรก มีโมเดลอย่าง `Post` และ `PostLike` ที่ไม่มีในระบบนี้ และชนกับแนวทาง Supabase
ที่เลือกไปแล้ว — ยังไม่ลบเพราะเป็นการตัดสินใจของเจ้าของระบบ
